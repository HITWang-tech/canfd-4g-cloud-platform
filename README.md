# 4G记录仪云平台

基于浏览器的 CANFD-4G 记录仪数据工作空间：仪表监测、时域 Scope、动态循环回放、GPS 定位与轨迹、原始报文检查及 CSV/PNG/GPX 导出。无需 MATLAB、Syslab 或本地计算程序。

## 使用

1. 打开 GitHub Pages 网页。默认载入标明“实车演示数据”的 2026-10-31 测试记录节选。
2. 点击“导入数据”：支持 HEX 日志 TXT/HEX、协议二进制 BIN、经典 CAN ASC、物理量 CSV/JSON，以及服务器原始 NDJSON 日志和快照 JSON。
3. 选择设备、CAN 通道和 ECU 源地址，查看仪表、Scope 和地图。
4. 底部控制播放、暂停、倍速、进度和循环；Scope 可选择窗口长度、缩放、修改图题/坐标/字号/图例并导出图片。
5. 发动机实际扭矩统一显示百分比（%），不换算为 N·m。

### 主页、时域与频域分析

- 首页按文档保留转速、车速、油门开度、瞬时油耗四个大仪表；四条小曲线分别显示车速、转速、油门与实际扭矩百分比，保留定位、航向与轨迹。界面以 100 ms 刷新，测量值仍使用原始报文时间与周期，不人为生成 100 ms 数据。未收到车速报文时，首页车速仪表默认显示 0 并明确标注；默认值不写入曲线、导出或分析。收到无效报文或已有值过期时保留原有无效／过期提示。
- 动力负载页显示六个仪表、需求与实际扭矩对比、动力响应、压力和进气流量曲线，以及 PTO 转速。PTO 可明确绑定独立 ECU；当前 DBC 没有 PTO 扭矩定义，N·m 保持缺失。
- 后处理排放页改为离线成果展示，使用原仿真分析系统生成的 NOx/CO₂/PM 出口排放速率原图和关键指标关联热力图，标明来源。图片保留原单位与字体，支持适应窗口、原始大小、放大/缩小、拖动和原图下载；不随实时轮询、设备/通道切换或回放游标变化。该页隐藏实时控制与回放条，切换到其他页面恢复。
- 展示素材是既有仿真分析成果，不代表当前车辆的实测排放。原始 MAT、厂家 DBC、实时日志和真实定位数据不随图片发布。整车/后处理字段仍可在时域页与信号核对表检查，实时动力负载页继续保留。
- 时域页可选择原有 22 项与文档新增连续量，状态码使用指示灯，不作为连续曲线。分组筛选候选列表；支持添加本组、选择全部有效信号、清空、图窗编辑及 PNG 导出。缺失信号不绘图，合法零值仍保留。浏览器保存信号选择。
- “频域与工作点”提供转速、实际扭矩百分比的波动功率谱及转速—扭矩工作点热力图，支持最近 60/120 秒或完整记录。分析对象是当前来源已载入数据的快照，不随回放游标截断；实时新增数据后点击“更新分析”。切换设备、通道、ECU 后清除旧来源的分析结果。
- 功率谱至少需要 64 个连续有效样本。重复时间戳取最后观测，空值切断片段；超过中位间隔 3 倍的缺口不连接。选最长片段，按中位间隔线性重采样，去均值、Hann 加窗、50% 重叠 Welch 平均并按采样率及窗能量归一化为单边 PSD；显示采样率、Nyquist 频率、频率分辨率及样本区间。上限 32768 点，近似恒定数据不绘制虚假主峰。它用于控制与负载波动观察，不替代机械振动测试。
- 工作点热力图对转速 > 0 rpm、转速与扭矩均有效且未超时的共同区间进行时间加权，颜色为有效停留时间占比；不按报文数量加权，不拼接不同通道或 ECU。缺失数据不足以计算时说明原因。

上传文件仅在当前浏览器解析，不上传到 GitHub 或项目服务器。文件不会自动写入仓库或浏览器永久存储。平台设置保存在当前浏览器；关闭页面后需要重新导入数据。访问令牌仅保留于当前页面会话。

网页资源采用相对路径，可部署到 GitHub Pages 项目子目录。ECharts 5.6.0 与 Leaflet 1.9.4 已随项目保存，绘图不依赖运行时 CDN；地图底图需要联网访问 OpenStreetMap，并保留版权标识。


### 固定通道分工与 IN1 传感器力

- CAN1：传感器力，记录仪配置为 500 kbit/s。只按提供的 DBC 解析标准帧 `0x301` 的 `IN1_Force_kN`：起始位 7、长度 16、大端（Motorola）、系数 0.002、偏移 0、DBC 声明有效范围 0–50 kN。D2–D7 不解码为其他力，当前仅显示一路 IN1。已按最新 adc_in1_force_10kN.dbc 的 SG_ 定义更新：原始值 2500=5 kN，5000=10 kN；文件标题/注释仍写旧系数 0.01，与实际定义不一致，解析以 SG_ 为准，未自行把声明上限 50 改为 10。
- CAN2：整车 J1939，记录仪配置为 250 kbit/s，保留原有 22 项目标量（21 项直接信号加 1 项积分燃油），新增 26 项文档相关数值与状态字段。通道、帧类型、CAN ID/PGN 同时匹配；同一报文移到错误通道不会套用另一通道的定义。
- 波特率由记录仪／CAN 硬件配置；网页接收已经采集到的字节，仅展示通道配置要求，不通过网页声称修改了硬件波特率。两个通道均可选择，即使某一路尚无数据也保留入口；缺失值不会填零。
- CAN1 首页显示实时 IN1 力值与曲线，时域页提供同一条力曲线，支持缩放、图例开关、坐标范围、字号和带标题的高分辨率 PNG 导出。空值与无效样本保留缺口，过期值明确标记。CAN2 保留整车仪表、时域、频域及工作点分析。
- 设置页分开导入 CAN1 力 DBC 与 CAN2 整车 DBC，各自更新对应通道。力 DBC 按 `IN1_Force_kN` 识别，必须是标准帧且单位为 kN；自定义定义仅在本次会话生效。原始 DBC 文件不上传。
- 演示数据来自用户提供的真实 CAN 表格 TXT，包含 CAN1 力值和 CAN2 整车数据；演示回放与实时接入明确区分。CSV 导出使用当前通道字段。

## 数据规则

信号解析检查、修复清单和验证范围见 [2026-10-29 解析检查报告](docs/decoder-audit-2026-10-29.md)。自定义 DBC 同时匹配目标 PGN 和信号名，拒绝冲突定义和不支持的目标编码。

- 按 CANFD-4G V1.1 的帧长度、序列号长度、类型和 XOR 校验解析；支持 TCP 拆包、粘包和 CAN/CAN FD 标准/扩展帧。
- 0x0F 为 CAN 上报，0x13 为定位上报，0x19 为心跳。CAN 数据和外层帧的字节序分别按 DBC 和协议处理。
- 目标字段保留原有 22 项，并新增 26 项文档相关数值与状态字段，共 48 项整车字段；CAN1 另有一路 IN1 力。大气压力/温度来自 AMB，最大可用扭矩来自 EEC2，行程燃油来自 LFC。
- 零值保留，空值/NaN/失效码不补零；未收到的仪表显示“—”。默认时效 3 秒；实时超时保留上次值并标记已过期，离线回放超时显示缺失。Scope 不跨长缺口连线。
- 显示与回放按设备、通道和 ECU 地址隔离，不把不同来源拼成同一条动力曲线。
- 计算油耗仅对有效燃油率做梯形积分，超过 5 秒或无效段不补算，不代表 ECU 生命周期总油耗。
- GPS 必须定位状态有效且经纬度有效、范围合理。协议对 2 字节速度/航向/海拔字段把有效位写为 bit16，存在冲突。默认按样例推定为 bit15，页面可改为严格模式（不解析这三项）；接实机前需厂家确认。经纬度按 WGS84 显示，协议未明确坐标基准，需实机核对。
- 地图按当前设备轨迹范围自适应，自动视野最高 19 级，显示米制比例尺。实时轮询和切换 CAN 通道/ECU 不重置视野；手动缩放后保持该比例尺，跟随只平移，手动拖动暂停跟随。“完整轨迹 / 自适应”恢复自动视野；自动模式仅在新增轨迹超出视野时重新适配，最多每秒一次。
- 底图与轨迹独立加载。标准底图使用 OpenStreetMap，科研低流量公开网页的备用底图使用 OSM France HOT，并保留全部版权标识；遵循 [OSM France 使用条件](https://www.openstreetmap.fr/usage/)。在图层上监听 `tileerror`，自动模式下失败或无图片加载超时 12 秒后尝试备用源；不无限切换重试。定位页可选择底图、手动重试，主页和定位页均显示底图状态。两套底图使用相同经纬度体系，不对原始轨迹进行偏移转换。
- 仓库包含用户授权用于公开演示的实车 CAN 记录节选与解析代码，不包含访问令牌、未发布协议原文、厂家 DBC、设备序列号；GPS 演示节选已获用户明确授权公开。

## 信号核对与 4G 转发筛选

数据与报文页覆盖平台全部 49 项信号：48 项整车字段与 CAN1 一路传感器力。列表显示通道、单位、DBC 报文或 CAN ID/PGN、参考信息、当前记录证据；累计燃油明确标记为积分计算量，不虚构独立报文。另保留原表的 3 项不监控信号和 1 项未定义 PTO 扭矩，便于核对。文档若与 DBC 不一致，按核验后的字节布局解析并列明差异，SPN 不作未经证实的映射。文档明确无效的喷油正时、灰载量、尿素供给压力不纳入监控。

- “导出全部待测清单”覆盖 CAN1 标准帧和 CAN2 全部直接信号的 DBC 定义，只用于现场验证，不代表设备已发出这些信号。
- “导出实测增补建议”只包含当前设备原始 CAN 中实际出现可解码样本的 ID/PGN，演示回放不会生成建议。掩码采用 1=参与匹配，配置厂家工具前核对其约定。
- 实测增补建议不能直接覆盖现有白名单；保留尚未出现的 CAN2 待测条件、GPS 和心跳。网页不直接写入记录仪配置。
- 历史轨迹可导入服务器保存的分日 NDJSON，再导出当前载入范围 GPX。原始日志服务器保留 30 天；网页不额外永久保存真实轨迹。

### 接收日志与报文分页

实时仪表使用当前设备、CAN 通道及 ECU 的最新接收值，与 GPS 时间和回放游标分离；曲线游标随所选 CAN 的最新报文推进。超过信号时效时保留上次值并明确标记已过期，新报文中的无效值仍显示为空。初次实时接入自动寻找包含目标信号的来源，用户手动选择后保持其选择。CAN 0 和 ECU 地址 0 均为有效选项。

- “数据与报文 → 接收日志”按每次网页轮询批次汇总新增字节、有效帧、校验/格式异常、有效目标信号和 GPS 有效性。首次拉取的已有记录标为历史，不计作本次新发送；收到不完整 TCP 帧时标为待观察，避免误判为无效数据。
- 日志覆盖所有设备与通道，保留当前页面最近 1000 条，支持导出 CSV。刷新会清空页面日志；Windows 接收端原始记录按北京时间每天写入 `data/records-YYYY-MM-DD.ndjson`；它与网页会话日志不同。
- “CAN 原始报文 → 信号解析”逐帧区分有效目标信号、目标信号全部无效、无匹配目标信号、远程请求和错误帧。有效数值 0 保留为有效。
- 表格支持首页、末页、页码跳转和每页 20/40/100/200 条。实时刷新保留选定页码；勾选“跟随最新（实时）”时自动进入末页，手动翻页后取消跟随。

Windows Server 使用 [Windows 部署说明](deploy/Windows部署.md)，包括已发布的安装脚本、自动启动任务及本机检查；TCP 接收和 HTTPS 网页接入分阶段验证。

GitHub Pages 只托管静态网页，不能接收设备 TCP 长连接。可将 `server/collector.mjs` 部署到有公网 TCP 端口的服务器，由设备连接该服务器，再通过 HTTPS 向网页提供数据。浏览器解析和绘图仍不依赖 Syslab。

### 本地开发

需要 Node.js 20 或以上，无需安装 npm 依赖：

```text
npm test
npm start
```

默认网页 `127.0.0.1:8880`，TCP `127.0.0.1:8890`。如端口被 Windows 保留，可用环境变量改为其他端口。

### 采集服务配置

| 环境变量 | 用途 |
| --- | --- |
| PORT / HOST | 网页及数据 API 监听地址，默认 8880 / 127.0.0.1 |
| RECORDER_TCP_PORT / RECORDER_TCP_HOST | 设备 TCP 监听地址，默认 8890 / 127.0.0.1 |
| RECORDER_API_TOKEN | 数据读取令牌，未配置时 API 不允许访问 |
| RECORDER_ALLOWED_ORIGINS | 允许访问 API 的网页 Origin，逗号分隔 |
| RECORDER_DEVICES | 允许的设备 SN，逗号分隔；空值不筛选 |
| RECORDER_LOG_DIR | 可选 NDJSON 日志目录，不设时仅保留内存记录 |
| RECORDER_CACHE_RETENTION_SECONDS | 内存记录保留秒数，默认 3600，以服务器接收时间判断 |
| RECORDER_CACHE_CLEANUP_SECONDS | 缓存清理间隔，默认 60 秒；查询快照时也清理 |
| RECORDER_CACHE_MAX_RECORDS | 缓存条数上限，默认 50000 |
| RECORDER_LOG_RETENTION_DAYS | 原始日志保留天数，默认 30 |

生产部署需 HTTPS 反向代理、TCP 端口与设备 SN 配置。该采集代码只实现文档明确的 CAN、定位、心跳接收与应答，不实现未定义的注册/鉴权流程，也不向车辆下发控制报文。

HTTPS API：`GET /api/snapshot?after=<cursor>`，请求头 `Authorization: Bearer <token>`。响应包含 `records`、`cursor`、`report`、`devices`，CAN payload 用字节数组传输。服务保留最近 1 小时内最多 50000 条内存记录；每分钟清理过期缓存，不断开 TCP、不重置游标或接收统计。响应的 `cache` 和 `storage` 提供当前缓存数量、保留策略、清理计数及存储错误状态。

### 缓存与原始日志定期清理

- 缓存按服务器 `receivedAt` 判断过期，不使用可能来自历史回放的设备时间。每分钟及快照查询时清理，清理过程保留设备连接、游标和累计接收计数。浏览器已经载入的回放数据与服务器缓存各自保存。
- 原始记录按北京时间每天归档；服务启动时及每小时检查一次，完整日文件中最新可能记录也超过 30 天且文件修改时间超过 30 天才删除，保证至少保留 30 天，最多额外保留约一天。只删除本程序命名的原始日志文件，不递归清目录，不删除令牌、连接配置、证书或安装文件。
- 升级时将已有 `data/records.ndjson` 原地重命名为带唯一标识的 `records-legacy-…ndjson`，保留内容与修改时间；这类旧归档同样按修改时间保留至少 30 天。不会把整个旧日志读入内存。
- 日志使用流式写入，遇到磁盘写入积压时暂停 TCP 读取、缓冲排空后继续；日志读写异常在 API 与网页实时状态中提示。服务关闭时刷新日志。
- Windows 配置可设置 `cacheRetentionSeconds`、`cacheCleanupSeconds`、`cacheMaxRecords`、`logRetentionDays`；旧配置缺少这些字段时采用上述默认值。修改后需重启接收服务。TCP 端口继续使用现有配置 58023。

安装更新先核验配置中的 HTTP/TCP 监听者，再停止已核实的本项目任务；兼容命令行路径中的正反斜杠和大小写。停止后等待端口释放，退出中的进程不误判为其他程序；只终止路径与脚本参数完全匹配的接收进程。停止阶段失败时尝试恢复原接收任务，无法核实的程序不会被终止。

## 验收界面

界面移除重复介绍、操作教程与算法长段说明，保留参数、单位、数据有效性、连接状态及简短来源标识。信号核对表继续保留解析依据；原图与采集、计算逻辑保持不变。

## 车速来源
