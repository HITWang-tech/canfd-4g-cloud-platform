# 信号解析检查与修复（2026-10-29）

## 结论

内置 21 项直接信号的位位置、长度、大小端、符号、比例、偏移、范围，与提供的原始 J1939 DBC 中对应 PGN 的定义一致。第 22 项累计燃油由燃油消耗率积分得到，不能当作 ECU 生命周期油耗。

检查发现并修复下列问题，不能据此宣称任何输入或设备固件下都绝对无误。

| 问题 | 影响与修复 |
| --- | --- |
| 自定义 DBC 只按信号名称覆盖 | 完整 DBC 的 DM4、ET3 等存在同名信号，可能覆盖 EEC1、CCVS1、ET1。改为同时匹配帧类型、PGN 和名称；同 PGN 冲突定义报错。另扫描全库的报文内部重复名称及载荷越界，返回结构提示，独立信号占位块不当作真实报文误报。 |
| DBC 导入未检查编码和单位 | 多路复用、浮点编码、越界位定义、非有限换算参数、单位不一致均明确拒绝，避免静默误解码。兼容摄氏度、小时、转速的等价单位写法。 |
| 物理量 JSON 的显式 null 被忽略 | 无效观测现在保留为空，清除旧值，燃油积分不会跨过该无效点。合法零值保留。 |
| 标准帧筛选使用空字符串 | 空字符串原本代表全部来源。标准帧改用独立选项，同时修正实时与离线筛选，保留 ECU 0 地址的合法性。 |
| 分段 CAN FD 载荷中的类似包头数据触发错误重同步 | 不在尚未收完的合法外层报文内部寻找新包。已知类型的明显非法长度立即拒绝；未知类型的不完整包按声明长度有界缓存。 |
| ACK 序列号经过 UTF-8 往返转换 | 回复直接回显原始设备序列号字节，避免非 UTF-8 字节变化。 |
| 有符号信号的负值误判失效码 | J1939 无符号失效码规则不应用于有符号二进制补码。原有 21 项直接定义均为无符号，扭矩的负百分比通过偏移表达。 |
| 积分输入未防御非有限值、未隔离设备 | 排除 NaN、无穷大、负燃油率；积分状态按设备、通道、ECU 隔离。 |
| ASC 数字被部分转换 | 严格校验十进制/十六进制数据字节及标准/扩展 CAN ID 范围。 |

## 验证

- 完整 Node 测试集：49 项通过，包括 TCP 接收、ACK、鉴权、源隔离、图表分析和新增解析边界用例。
- 使用独立 cantools 数值解码器，对照原始 DBC 核对全部 21 项直接定义，21,000 组确定性随机载荷数值比较一致。应用层失效码、范围及燃油温度 -40 ℃ 规则另外检查。
- 原始 ASC：9,974 帧，解析格式异常 0；其中 2,263 帧匹配目标信号。4,166 个目标值与独立数值解码结果及应用层有效性规则一致。
- 上传完整原始 DBC 后更新 21 项定义，ASC 的目标值与内置定义结果一致，诊断同名字段不再覆盖目标报文。
- 独立解码检查中，cantools 对 VECTOR__INDEPENDENT_SIG_MSG 独立信号占位块的枚举存在兼容性限制，因此仅在内存副本中跳过 VAL_ 枚举文本。该占位块并非实际 CAN 报文，也不能仅据此判定 DBC 错误；未修改原文件、信号位定义或换算参数。枚举文本不参与此次物理数值比较。
- 所有原始 DBC、ASC、独立参考结果留在本机，未加入公开仓库。

## 适用范围与需要确认的部分

- 支持目前目标表中单帧整数编码信号；不实现 J1939 TP 多包重组，不等于完整 J1939 协议栈。ASC 导入目前支持经典 CAN 格式；协议二进制接入支持 CAN FD。
- 两字节 GPS 字段的有效位在厂家文档中存在矛盾，默认按样例解释 bit15，设置中保留严格模式，需要厂家确认。经纬度坐标基准也需实机核对。
- 显示“有原始报文”不代表报文含目标 PGN；失效码、不同 ECU 或不同通道数据不会强行拼接成有效物理量。SensorCAN ADC 展示不在本次范围内。
- 燃油积分只覆盖当前已载入的有效记录，间隔超过 5 秒或无效点不补算。实时浏览器最多保留 100,000 条记录，服务内存最多 50,000 条；不能把缓存区间积分当成自服务启动以来的完整累计量。
- 前端刷新生效。TCP 拆包与 ACK 的修复需要更新云服务器接收服务；网页发布不自动修改已安装的服务器程序。
